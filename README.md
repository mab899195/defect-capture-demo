# Defect Capture (demo)

A mobile-first demo web app for concrete defect inspections. A field inspector
logs defects with a photo, a defect type, a condition state and a map pin. An
office engineer reviews them on a map, records a decision, and exports a PDF.

It is a static site with no backend: plain HTML, CSS and JavaScript, ready for
GitHub Pages.

- All data is sample data stored as files in this repo (`data/`, `images/`).
- New defects and engineer decisions work in the browser but **reset on page
  reload**. Nothing is uploaded or saved anywhere.
- No login, no AI, no Microsoft or SharePoint dependency.

## What is in the demo

| Link | Opens |
|---|---|
| `index.html` | Home: list of sample projects |
| `?project=bridge-demo` | Alder Creek Bridge (Design Office A), Field view |
| `?project=parking-demo` | Northgate Parking Structure (Design Office B), Field view |
| `?project=bridge-demo&view=office` | The same project, Office view |

**Field view**: "My defects" for the selected inspector (switch with the
"Logged by" picker). Revisit requests are listed first with an orange border
and the engineer's comment. "Add defect" opens the camera or photo library,
then a form with defect type, condition state, map pin, notes and a required
"Logged by" name.

**Office view**: map with numbered pins coloured by condition state, a list
sorted worst first, and a detail panel where the engineer sets a status (No
action, Repair, Reinforce, Revisit) and a comment. A revisit needs a comment;
it then shows up as a flag in the Field view. The **PDF** button exports the
project's defect list as a US Letter report.

## Run it locally

The app loads its JSON with `fetch`, so open it through a local web server
rather than by double-clicking `index.html`:

```bash
cd defect-capture-demo
python3 -m http.server 8000
# then open http://localhost:8000
```

Any static server works (`npx serve`, the VS Code Live Server extension, ...).

To try it on your phone, start the server, make sure the phone is on the same
Wi-Fi, and open `http://<your-computer-ip>:8000`. Note that the "Use my
location" button needs HTTPS on phones, which GitHub Pages provides.

## Publish on GitHub Pages

1. Push this repository to GitHub (the files must be at the repository root,
   with `index.html` at the top level).
2. On GitHub, open the repository and go to **Settings > Pages**.
3. Under **Build and deployment**, set **Source** to **Deploy from a branch**.
4. Choose the branch (for example `main`) and the folder **/ (root)**, then
   click **Save**.
5. Wait a minute or two. The page shows the live address, usually
   `https://<your-user>.github.io/<repository-name>/`.
6. Share project links by adding the query string, for example
   `https://<your-user>.github.io/<repository-name>/?project=bridge-demo`.

There is no build step. Every push to the selected branch republishes the
site. The empty `.nojekyll` file tells GitHub Pages to serve the files as they
are.

## Swap in real photos

Each defect's photo path is set in its project file, for example
`"photo": "images/bridge-demo/D-02.jpg"` in `data/bridge-demo.json`.

- **Simplest:** replace the file with a real photo of the same name (for
  example save your photo as `images/bridge-demo/D-02.jpg`). JPEG is
  recommended. A 4:3 landscape photo around 1200 px wide looks best and keeps
  the PDF small.
- **Different file name or format:** put the file in the project's images
  folder and change the `photo` value in the JSON to match.

The placeholders were generated by `tools/make_placeholders.py`
(`pip install pillow`, then `python tools/make_placeholders.py`). Running it
again **overwrites** every photo listed in the JSON files, so do not run it
after adding real photos.

## Change the sample data

Each project is one JSON file in `data/`, listed in `data/projects.json`.

```jsonc
{
  "id": "bridge-demo",                    // used in the link: ?project=bridge-demo
  "structureType": "Bridge",              // label on the home card
  "structureName": "Alder Creek Bridge",
  "designOffice": "Design Office A",
  "defaultInspector": "J. Ortiz",         // whose list the Field view shows first
  "map": { "center": [34.12722, -117.86520], "zoom": 18 },
  "defects": [
    {
      "id": "D-02",
      "photo": "images/bridge-demo/D-02.jpg",
      "type": "exposed_rebar",            // cracking | delamination | spalling | efflorescence | exposed_rebar
      "conditionState": 4,                // 1 good, 2 fair, 3 poor, 4 severe
      "lat": 34.12731,
      "lng": -117.86509,
      "location": "Soffit, span 2",       // short element label shown in lists (optional)
      "notes": "Two bottom bars exposed ...",
      "loggedBy": "J. Ortiz",
      "loggedAt": "2026-10-20T09:41:00",  // local time
      "engineerStatus": "revisit",        // no_action | repair | reinforce | revisit | null (not reviewed)
      "engineerComment": "Need a close-up ..."
    }
  ]
}
```

To add a project, copy one of the JSON files, give it a new `id`, add it to
`data/projects.json`, and put its photos in `images/<id>/`.

## Extend the PDF report

The report is built in `js/pdf/`:

- `report.js` runs the sections listed in `REPORT_SECTIONS` in order and adds
  page numbers and footers.
- `sections.js` contains the sections (header, summary, defect rows) and the
  `DEFECT_FIELDS` list.

To add a **field** to every defect row, add an entry to `DEFECT_FIELDS`:

```js
{ label: 'Element', width: 'col', value: (d) => d.location }
```

`width: 'col'` puts it in a three-column grid; `width: 'full'` gives it the
whole text column. Empty values are skipped.

To add a **section** (for example a sign-off block), write a function
`(ctx) => { ... }` in `sections.js` that draws with `ctx.doc` (a jsPDF
document), calls `ctx.ensureSpace(height)` before drawing, and moves `ctx.y`
down. Then add it to `REPORT_SECTIONS` in `report.js`.

## Project layout

```
index.html            single page; loads Leaflet, jsPDF and js/app.js
css/styles.css        design tokens and all styles
js/app.js             routing (?project=..., &view=office) and the project header
js/data.js            loads JSON, keeps session changes in memory
js/constants.js       defect types, condition states, engineer statuses
js/ui.js              shared helpers (chips, icons, dates, toast)
js/home.js            project list
js/field.js           Field view and Add defect screen
js/office.js          Office view, map, list and detail panel
js/map.js             Leaflet map, numbered pins, pin-drop picker
js/pdf/report.js      PDF export runner
js/pdf/sections.js    PDF sections and defect fields
data/                 project JSON files
images/               defect photos, one folder per project
tools/                placeholder photo generator
```

## Libraries and credits

- [Leaflet](https://leafletjs.com/) 1.9.4 for maps, with
  [OpenStreetMap](https://www.openstreetmap.org/copyright) tiles (no API key).
  OpenStreetMap's public tile servers are fine for a demo; for heavy use,
  switch to a tile provider in `js/map.js`.
- [jsPDF](https://github.com/parallax/jsPDF) 2.5.1 for the PDF export.
- [Inter](https://rsms.me/inter/) via Google Fonts.

Libraries load from cdnjs, so the app needs an internet connection.

Condition states follow the four-state approach of the AASHTO element-level
inspection framework. Sample structures, people and coordinates are fictional.
